# CRUD API для Yatube

Учебный REST API для публикаций, групп и комментариев. Вся логика API
находится в приложении `api`, модели — в приложении `posts`.

Проект проверен на Python 3.12.9, Django 5.1.1 и Django REST Framework 3.15.2.
Версии зависимостей зафиксированы в `requirements.txt`.

**Если впервые работаешь с Postman:** открой
[пошаговый практикум по нашему API](POSTMAN_GUIDE.md).
В нём показано, куда вводить адрес, заголовки и JSON, как получить токен,
создать пост и комментарий, проверить права и разобраться с ошибками.

## Возможности и права доступа

- Доступ к ресурсам только по токену (`TokenAuthentication`).
- Публикации и комментарии: просмотр, создание, изменение и удаление.
- Изменять и удалять публикацию или комментарий может только его автор.
- Группы: только просмотр через API; создавать группы можно в админке Django.
- Комментарии выбираются в пределах публикации, указанной в URL.
- Автор определяется по токену, публикация комментария — по URL.
- Списки возвращаются без пагинации.

## Запуск в Windows PowerShell

Команды выполняются из корня репозитория `api-yatube`, где лежит
`requirements.txt`. Для нового окружения установите Python 3.12 и выполните:

```powershell
py -3.12 -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если окружение уже создано и зависимости установлены, эти команды повторять
не нужно. Ниже Python запускается по полному относительному пути, поэтому
активация окружения не требуется.

Подготовьте базу данных и создайте пользователя для админки и проверки API:

```powershell
.\venv\Scripts\python.exe yatube_api/manage.py migrate
.\venv\Scripts\python.exe yatube_api/manage.py createsuperuser
.\venv\Scripts\python.exe yatube_api/manage.py runserver
```

Введите логин и пароль в интерактивном диалоге `createsuperuser`.
API: `http://127.0.0.1:8000/api/v1/`.
Админка: `http://127.0.0.1:8000/admin/`.
Базовый префикс `/api/v1/` сам по себе не является страницей со списком маршрутов.

Через админку можно создать группы и дополнительных пользователей.
Регистрация пользователей через API не предусмотрена.
Даже суперпользователь через API может изменять только свой контент.

Настройки проекта предназначены для локальной учебной разработки
(`DEBUG=True`, SQLite, учебный `SECRET_KEY`), а не для публичного развёртывания.

## Эндпоинты

Все пути указаны относительно `http://127.0.0.1:8000/`.

| Путь | Методы | Назначение |
| --- | --- | --- |
| `api/v1/api-token-auth/` | POST | Получить токен по логину и паролю |
| `api/v1/posts/` | GET, POST | Список публикаций, создание публикации |
| `api/v1/posts/{post_id}/` | GET, PUT, PATCH, DELETE | Работа с публикацией |
| `api/v1/groups/` | GET | Список групп |
| `api/v1/groups/{group_id}/` | GET | Просмотр группы |
| `api/v1/posts/{post_id}/comments/` | GET, POST | Комментарии публикации, создание комментария |
| `api/v1/posts/{post_id}/comments/{comment_id}/` | GET, PUT, PATCH, DELETE | Работа с комментарием публикации |

## Примеры запросов

Примеры можно отправить из Postman: выберите метод и URL, для тела запроса
выберите JSON и укажите `Content-Type: application/json`.

### Получение токена

`POST /api/v1/api-token-auth/`

```json
{
  "username": "your_username",
  "password": "your_password"
}
```

Укажите данные существующего пользователя. Ответ содержит поле `token`.
Токен для самого запроса получения токена не требуется.
В остальные запросы добавьте заголовок:

```http
Authorization: Token <полученный_токен>
```

### Создание публикации

`POST /api/v1/posts/`

```json
{
  "text": "Моя первая публикация"
}
```

Ответ со статусом `201` содержит `id`, `text`, `author` (имя пользователя),
`image`, `group` и `pub_date`. Для привязки к группе добавьте поле `group`
с ID существующей группы. Без группы поле ответа будет `null`.
Для загрузки изображения отправляйте `multipart/form-data` с файлом в поле
`image` и текстом в поле `text`; клиент должен сам сформировать Content-Type
с границей частей (boundary).

### Создание комментария

`POST /api/v1/posts/14/comments/`

```json
{
  "text": "Интересная публикация!"
}
```

Замените `14` на ID созданного поста. Ответ со статусом `201` содержит
`id`, `author`, `post`, `text`, `created`. Передавать автора и публикацию
в теле запроса не нужно: сервер назначает их самостоятельно.

### Изменение и удаление

Для изменения текста отправьте `PATCH` на адрес конкретного поста или
комментария с JSON `{"text": "Новый текст"}`. В ответ придёт изменённый
объект и статус `200`. `PUT` также поддерживается; обязательный текст
нужно передать в теле запроса.

Для удаления отправьте `DELETE` на тот же адрес. Успешный ответ — `204`
без тела. Для проверки прав создайте второго пользователя и попробуйте
изменить чужой контент с его токеном: ожидается `403`.

### Коды ошибок

- `400` — некорректные данные, например пустой текст или неверные данные входа.
- `401` — токен отсутствует или недействителен при обращении к ресурсам.
- `403` — попытка изменить или удалить чужой контент.
- `404` — объект отсутствует либо комментарий не принадлежит посту из URL.
- `405` — метод не поддерживается, например POST для групп
  от аутентифицированного пользователя.

## Проверки

Из корня репозитория:

```powershell
.\venv\Scripts\python.exe -m pytest
.\venv\Scripts\python.exe yatube_api/manage.py check
.\venv\Scripts\python.exe yatube_api/manage.py makemigrations --check --dry-run
.\venv\Scripts\python.exe -m flake8
```

Pytest использует отдельную тестовую базу. Дополнительные проверки
`tests/test_comment_boundaries.py` проверяют принадлежность комментария
публикации, отсутствие родительского поста и удаление своего комментария.

Готовая коллекция запросов находится в `postman_collection/`.
Инструкция — в [postman_collection/README.md](postman_collection/README.md).
Её скрипт подготовки `set_up_data.sh` очищает существующую базу данных:
используйте его только для отдельной тестовой базы. Для ручных запросов
из примеров выше этот скрипт не нужен.
