# Postman: практикум на API Yatube

Проходи инструкцию по порядку. Сначала получи один успешный ответ, затем
переходи к следующему запросу. Запросы меняют настоящую локальную базу проекта,
поэтому для упражнения создавай отдельные учебные публикации.

## 1. Зачем нужен Postman

Postman — клиент: он отправляет запросы нашему Django-серверу и показывает
ответы. Сервер хранит данные и проверяет права. Postman сам не запускает
Django и не создаёт базу данных.

У запроса есть четыре главные части:

| Часть | Что означает | Пример |
| --- | --- | --- |
| Метод | Какое действие выполнить | GET — прочитать, POST — создать |
| URL | К какому ресурсу обратиться | `http://127.0.0.1:8000/api/v1/posts/` |
| Headers | Дополнительная информация | Токен пользователя |
| Body | Данные для отправки | Текст новой публикации |

После отправки смотри статус ответа и его тело. Например, `201 Created`
означает, что объект создан; JSON ниже содержит данные этого объекта.

## 2. Подготовь сервер

Для работы с локальным проектом удобно настольное приложение Postman.
Если используешь веб-версию, для этих инструкций выбери запущенный Desktop
Agent: запросы должны доходить до сервера на твоём компьютере.

В Git Bash выполни:

```bash
cd ~/Desktop/Projects_python/api-yatube
source venv/Scripts/activate
cd yatube_api
python manage.py migrate
```

Если пользователя для входа ещё нет, создай его:

```bash
python manage.py createsuperuser
```

Задай логин и пароль. При вводе пароля символы в терминале не отображаются.
Если пользователь уже есть и ты помнишь его пароль, повторно создавать его
не нужно. Пароль от аккаунта Postman здесь не подходит: нужен пользователь Django.

Запусти сервер:

```bash
python manage.py runserver
```

Должна появиться строка с `http://127.0.0.1:8000/`. Оставь терминал открытым.
Остановка — Ctrl+C. Если сервер уже работает, запускать второй не нужно.

Страница `/` возвращает 404 — это нормально, у нас нет главной страницы.
Админка находится по адресу `http://127.0.0.1:8000/admin/`.

## 3. Открой запрос в Postman

Открой новую вкладку запроса кнопкой `+` / `Add`. В интерфейсах, где предлагается
выбор типа, выбери `HTTP` (также может быть доступно `New → HTTP Request`).

Найди элементы:

- Выпадающий список `GET` слева от строки URL — выбор метода.
- Поле URL — сюда вставляется полный адрес, без слова POST или GET перед ним.
- `Send` — отправить запрос.
- `Headers` — таблица заголовков с колонками Key и Value.
- `Body` — данные запроса.
- `Authorization` — настройки автоматической авторизации.

В этом практикуме выбирай `Authorization → No Auth` и добавляй токен вручную
в `Headers`. `No Auth` отключает автоматическое добавление авторизации;
заголовок, который ты введёшь вручную, всё равно будет отправлен.

Ответ появляется в отдельной области под запросом. Не путай Body запроса,
который редактируешь ты, и Body ответа, который прислал сервер.

## 4. Получи токен

1. Выбери метод **POST**.
2. Вставь URL:

   ```text
   http://127.0.0.1:8000/api/v1/api-token-auth/
   ```

3. Выбери `Authorization → No Auth`. Если в Headers уже есть Authorization,
   удали или отключи эту строку: для получения токена она не нужна.
4. Перейди в `Body`, выбери `raw`, затем формат `JSON`.
5. Вставь следующий текст, заменив значения на данные своего пользователя Django:

   ```json
   {
     "username": "твой_логин",
     "password": "твой_пароль"
   }
   ```

6. Нажми `Send`.

При выборе JSON Postman автоматически задаёт `Content-Type: application/json`.
Не добавляй второй такой же заголовок. Если ранее задавал Content-Type вручную,
проверь, что он не противоречит выбранному формату.

Успех — статус **200 OK** и ответ такого вида:

```json
{
  "token": "значение_твоего_токена"
}
```

Скопируй только значение токена: без кавычек, фигурных скобок и слова `token`.
Этот запрос проверяет существующего пользователя, а не регистрирует нового.
Не публикуй настоящий токен и пароль в репозитории или общих коллекциях.

## 5. Прочитай список публикаций

Создай новую вкладку HTTP-запроса:

1. Метод: **GET**.
2. URL: `http://127.0.0.1:8000/api/v1/posts/`.
3. `Authorization`: **No Auth**.
4. `Body`: **none**.
5. В `Headers` добавь включённую строку:

   | Key | Value |
   | --- | --- |
   | Authorization | `Token значение_твоего_токена` |

6. Нажми `Send`.

Между `Token` и значением нужен один пробел. Не добавляй кавычки или угловые
скобки. Для нашего API используется префикс **Token**, а не Bearer.

Ожидается **200 OK**. Если публикаций нет, тело ответа будет:

```json
[]
```

Это успешный ответ с пустым списком. Если записи уже есть, увидишь список объектов.

Для каждого следующего запроса к ресурсам тоже добавляй этот заголовок.
В новой вкладке он не появится сам. Для начала можно дублировать уже
настроенный запрос и менять его метод, URL и Body.

## 6. Создай публикацию

1. Метод: **POST**.
2. URL: `http://127.0.0.1:8000/api/v1/posts/`.
3. В Headers — тот же Authorization с твоим токеном.
4. `Body → raw → JSON`:

   ```json
   {
     "text": "Учусь отправлять запросы через Postman"
   }
   ```

5. Нажми `Send` один раз.

Ожидается **201 Created**. Пример ответа (числа, имя и дата у тебя будут свои):

```json
{
  "id": 14,
  "text": "Учусь отправлять запросы через Postman",
  "author": "anton",
  "image": null,
  "group": null,
  "pub_date": "2026-09-27T10:00:00Z"
}
```

Запиши ID созданного поста. Ниже число **14 — пример**: в адресах заменяй его
на свой ID. `null` у изображения и группы означает, что они не заданы.
Автор назначается сервером по токену.

Каждый повторный POST создаёт ещё одну публикацию. Чтобы проверить результат,
отправляй GET, а не повторяй создание.

## 7. Прочитай и измени свой пост

Чтение одной публикации:

- Метод: **GET**.
- URL: `http://127.0.0.1:8000/api/v1/posts/14/`.
- Headers: твой токен.
- Body: **none**.
- Ожидается **200 OK** и объект публикации.

Изменение текста:

- Метод: **PATCH**.
- URL: тот же адрес конкретной публикации.
- Headers: твой токен.
- `Body → raw → JSON`:

  ```json
  {
    "text": "Теперь я умею изменять публикации через API"
  }
  ```

- Ожидается **200 OK**, тот же ID и новый текст.

PATCH меняет переданные поля. PUT также поддерживается: для нашего API
при PUT обязательно передать текст. Для упражнения с одним полем используй PATCH.

## 8. Создай и измени комментарий

Создание:

- Метод: **POST**.
- URL: `http://127.0.0.1:8000/api/v1/posts/14/comments/`.
- Headers: твой токен.
- `Body → raw → JSON`:

  ```json
  {
    "text": "Мой первый комментарий"
  }
  ```

Ожидается **201 Created**. В ответе будут `id`, `author`, `post`, `text`, `created`.
Запиши ID комментария. Предположим, он равен **4**.
ID поста и ID комментария — разные значения, они не обязаны совпадать.

| Действие | Метод | URL |
| --- | --- | --- |
| Прочитать все комментарии поста | GET | `http://127.0.0.1:8000/api/v1/posts/14/comments/` |
| Прочитать один комментарий | GET | `http://127.0.0.1:8000/api/v1/posts/14/comments/4/` |
| Изменить комментарий | PATCH | `http://127.0.0.1:8000/api/v1/posts/14/comments/4/` |

Для GET выбирай Body none. Для PATCH передай JSON `{"text": "Исправленный комментарий"}`.
Для всех запросов нужен токен. Успешное чтение и изменение возвращают **200 OK**.
Если указать ID комментария под другим постом, вернётся **404**.

## 9. Поработай с группами

Отправь GET с токеном и Body none:

```text
http://127.0.0.1:8000/api/v1/groups/
```

Ответ **200 OK** и `[]` означает, что групп пока нет. Чтобы создать группу:

1. Открой в браузере `http://127.0.0.1:8000/admin/`.
2. Войди как суперпользователь.
3. Найди модель групп приложения **Posts**. Не перепутай с группами прав
   пользователей в разделе аутентификации Django.
4. Создай группу: название `Математика`, slug `math`, описание `Посты о математике`.
5. Повтори GET в Postman и возьми ID из ответа.

Одна группа: GET `http://127.0.0.1:8000/api/v1/groups/2/`, где 2 — её реальный ID.

Чтобы привязать созданный пост к группе, отправь PATCH на адрес поста:

```json
{
  "group": 2
}
```

Заменяй 2 на существующий ID. Ожидается 200 и изменённое поле `group`.
Для удаления связи можно отправить `{"group": null}`.
POST, PUT, PATCH и DELETE для самих групп через API не предоставляются.

## 10. Проверь права доступа

Сначала создай второго обычного пользователя через раздел пользователей админки.
Ему не требуется доступ в админку. Получи его токен отдельным запросом из шага 4.
Сохрани различие между токенами первого и второго пользователей.

1. Отправь GET своего поста с токеном второго пользователя — ожидается **200**.
2. Отправь PATCH того же поста с токеном второго пользователя и валидным текстом — **403**.
3. Повтори проверку PATCH для комментария первого пользователя — **403**.
4. Удали или отключи строку Authorization и отправь GET списка постов — **401**.
5. Верни токен первого пользователя. Отправь POST публикации с `{"text": ""}` — **400**.

Это ожидаемые ответы: сервер демонстрирует, что проверяет права и данные.
Вход в админку в браузере не добавляет токен в Postman.

## 11. Удали учебные данные

Удаление выполняй после остальных упражнений и только для созданных в них объектов.
Используй токен их автора, Body none.

1. DELETE `http://127.0.0.1:8000/api/v1/posts/14/comments/4/` → **204 No Content**.
2. GET этого комментария → **404**.
3. DELETE `http://127.0.0.1:8000/api/v1/posts/14/` → **204 No Content**.
4. GET этого поста → **404**.

Пустое тело ответа 204 нормально. Удаление поста также удаляет его комментарии.

## 12. Как сохранять запросы

Коллекция — папка с сохранёнными запросами. Создай свою коллекцию, например
`Yatube — обучение`, и сохраняй запросы кнопкой Save, выбирая эту коллекцию.
Названия удобно давать по действиям: `01 — Получить токен`, `02 — Список постов`,
`03 — Создать пост`. В сохранённых адресах после удаления объектов потребуется
обновлять ID. Не публикуй коллекцию с настоящими учётными данными.

В проекте уже есть `postman_collection/CRUD_for_yatube.postman_collection.json`.
Его можно открыть через Import. Для полного запуска этой готовой коллекции
нужны предусмотренные ею начальные данные: смотри её отдельный README.
Импорт не создаёт эти данные. Скрипт `set_up_data.sh` очищает базу, поэтому
для текущего практикума его не запускай. Ручные упражнения выше самостоятельны.

## 13. Если запрос не работает

| Что видишь | Что проверить |
| --- | --- |
| Could not send request / ECONNREFUSED | Работает ли runserver; совпадает ли порт; используется ли HTTP; для веб-версии выбран ли Desktop Agent |
| 400 при получении токена | Логин и пароль пользователя Django, JSON, имена username и password |
| 400 при создании | Прочитай Body ответа: там указано поле с ошибкой; проверь непустой text и существующий group |
| 401 | В Headers включён Authorization, значение имеет вид Token + пробел + токен; токен скопирован целиком |
| 403 | Кто автор объекта и чей токен отправлен |
| 404 | Полный URL, ID, принадлежность комментария посту; корень сайта и /api/v1/ не являются страницами списка |
| 405 | Метод: например, токен получают POST, а группы читают GET |
| 415 | Для JSON выбраны Body → raw → JSON; нет конфликтующего Content-Type |
| 500 | Посмотри traceback в терминале Django; это ошибка сервера, а не успешный ответ |
| 200 и [] | Запрос успешен, но список пуст |
| 204 без JSON | Удаление успешно, тело ответа не предусмотрено |

Пиши адреса с завершающим `/`, как в примерах. В JSON используй двойные кавычки
и не ставь запятую после последнего поля. В URL вставляй числа без `{}`, `<` и `>`.

Если понадобится помощь, покажи метод, URL, статус и тело ответа. На скриншоте
скрой пароль и токен.
